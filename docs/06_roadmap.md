# Prime Flight — 12-місячний roadmap

Джерела: слайд «Prime Flight — 12-Month High-Level Roadmap» + пост ліда в Slack (делівері по кварталах).
Головний бізнес-KPI — **Time to Result** (від завершення події до результату на RampVision). Цілі ілюстративні,
підлягають валідації замірами (baseline: PF-Q1-08).

## Вересень — планування
- Підтвердити baseline і delivery KPI.
- Узгодити напрям архітектури (дві гілки, stage detector як оркестратор, ієрархія GM → група → модуль).
- Підтвердити пріоритети й припущення roadmap (дедлайн roadmap ≥3 міс.: нд 14.09.2026).

## Q1 (місяці 1–3) — Continuous Upload + Faster Post-Processing

**Що робимо.** Мінімальна зміна поточної архітектури з максимальним виграшем у часі:
1. CameraBox вивантажує чанки по **Wi-Fi/SIM під час запису**, все інше лишається як є → прибираємо довге чекання перед upload.
2. **Stage detector** + прибираємо merge з раннього етапу: не чекаємо, поки всі чанки замерджаться, а ранимо GM/трекер/модулі
   **по чанках** і отримуємо результат швидше. Merge лишається для архіву й пост-модулів.
3. Паралельно Валентин + Юрій **фіксять GM і Tracker** (гігієна контракту, `schema_version`, один трекер на подію,
   витікання полів, `pushback_attached` причинно).

**Власники.** Пункти 1–2 — Максим Чернишов. Пункт 3 — Валентин + Юрій Лучко.
**Delivery клієнту.** Відео починає надходити на сервер, поки CameraBox ще пише. Time to Result ~24h → ~15h.

## Q2 (місяці 4–6) — Real-Time Architecture Foundation

**Що робимо.**
1. Максим готує **окрему гілку real-time** (покадрове, не чанкове, завантаження; ціль до ~3 с для підтримуваних перевірок).
2. Валентин + Юрій **підлаштовують GM і Tracker** під RT-гілку (бюджет 125 мс/кадр; RT-GM ≈ 6 класів; batching/ONNX).
3. Беремо **один перший модуль** для інтеграції в RT. Стратегія-хедж: є модулі, що працюють лише з контракту й не залежать від
   змін GM/Tracker (E0: beltloader-chocks, pushback-does-not-start, pushback-pathway) — навіть якщо GM/Tracker для RT
   не встигають, клієнту показуємо модуль, що вже працює в real-time.

**Delivery клієнту.** Перші CV-модулі дають результат до того, як повне відео змерджене й оброблене.

## Q3 (місяці 7–9) — Real-Time Expansion + Alerting

**Що робимо.**
1. Продовжуємо перенос модулів у RT (E0 → E1 → PATCH-модулі через подію детектора).
2. **Аріан Сінгх — алертинг**: бекенд-алерти/нотифікації для важливих safety-івентів (дедуплікація, вікна тиші, MongoDB,
   endpoint, рендеринг на RampVision).
3. У Максима — час на **фікси архітектури**, дороблення гілок, техборг (уніфікація пінів cv_common, gzip, dead models).
4. Трек «перевизначення тригера» для S1-перевірок (safety zone, pathway, walkers, hand signals).

**Delivery клієнту.** Більше пріоритетних модулів у RT; важливі safety-івенти тригерять алерти для менеджерів станцій.

## Q4 (місяці 10–12) — Maximum Real-Time Coverage + Optimization

**Що робимо.**
1. Переносимо **усі практично можливі модулі** в RT (E2 з моделями, E4/RETHINK; POST-модулі лишаються в пост-гілці).
2. **Оптимізуємо GM і Tracker** (TensorRT/fp16, роздільна здатність, ресурси).
3. Оптимізація на рівні архітектури / інших компонентів (stage detector v1, receiver, зменшення compute).
4. **Стрімінг гейтів на RampVision** (live-вигляд гейта).

**Delivery клієнту.** Максимум практичних RT-перевірок + оптимізована пост-обробка для решти. Time to Result ~5–6h для пост-частини.

## KPI-лінія

`Current ~24h → Q1 ~15h* → Q2 further reduced → Q3 further reduced → Q4 ~5–6h*` (для пост-гілки; RT-перевірки — секунди
після події, нижня межа = затримка події трекера 4 с / 10 с).

## Ризики (жива секція, оновлює pm-coordinator)

- Транспорт з гейта (Wi-Fi/SIM, VPN, ≈4 Мбіт/с × 2 камери × N гейтів) — поза CV-зоною, потрібне рішення інфри.
- GPU-раннер для nightly-паритету відсутній → регресії видно лише вручну.
- Розмітка fail-кейсів майже порожня для 3 з 4 перевірок першої черги → «доставлено» без заміру на fail-відео не оголошуємо.
- Різні піни cv_common у модулях → спільні компоненти (stage detector, контракт) ламають модулі тихо.
- S1-перевірки ретроспективні за логікою → RT без зміни тригера не дає превенції.
