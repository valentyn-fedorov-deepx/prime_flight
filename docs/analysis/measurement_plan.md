# План замірів: baseline і доказ «точність модулів не впала» для GM v2 / Tracker v2

Статус: чернетка ліда 2026-09-14 (PF-Q1-15). Уточнюється після `gm_current.md`, `module_consumption.md`,
`contract_observed.md`. Правило з CLAUDE.md: парне порівняння на тих самих відео валідне завжди; абсолютна точність —
лише там, де є fail-розмітка.

## 1. Що саме міряємо (три рівні, від дешевого до дорогого)

| Рівень | Питання | Метод | Інструмент | Дані |

## 2. Умови вимірювання (без цього цифри не приймаються)

- Декодер закріплений з обох боків (X4): один і той самий (OpenCV; ffmpeg губить кадри на немонотонному DTS).
- Повний turnaround, не уривок (короткі тести завищують швидкість: 4,72× vs 3,95×).
- Вільна машина; стан файлового кешу однаковий для обох режимів (холодний/прогрітий зсуває вдвічі).
- Ваги, роздільна здатність (1088 GM / 1280 chocks), пороги і параметри трекера (MAX_AGE 40, MIN_HITS 8) зафіксовані і
  записані у звіт; будь-яка зміна — окремий рядок таблиці, а не «покращення».
- Нумерація кадрів 1-based по `frame_id`; кількість кадрів = кількість рядків ndjson (перевірено на стенді: збіг до одиниці).

## 3. Критерії прийняття для GM v2 / Tracker v2 (пропозиція до узгодження з Ігорем/Оксаною)

1. L1 GM: `frame_parity ≥ 0.99` при ndigits=1 на кожному з 7 відео, **або** кожна розбіжність пояснена механізмом
   (інша версія NMS, fp16, батчинг) і не змінює L2.
2. L1 Tracker: 100 % збіг по споживаних не-приватних полях (`arrival_frame`, `departure_frame`, статуси, `_class_name`,
   `_obj_id`-ідентичність за IoU) з допуском ±1 кадр на події; кількість унікальних літаків на відео = як у v1 (X1).
3. L2: 0 змін вердиктів на ATL-C5 і на збалансованій вибірці; зміна «Not observed → вердикт» рахується окремо і
   пояснюється.
4. L3: recall/precision не гірше v1 на Main gear chocks (30 fail) — єдина перевірка з достатньою розміткою.
5. Швидкість: GM v2 ≤ 28 мс/кадр на референс-залізі; трекер ≤ 1 мс; end-to-end ≥ 3,95× real-time на повному turnaround.
