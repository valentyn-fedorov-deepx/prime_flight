# What a module would need from a model of its own

Generated by `scripts/module_dataset_needs.py` from `docs/analysis/module_consumption.json` (static analysis of the module code) and `pf/rt/declarations.json` (corrections found by running the checkouts the test set uses); the grouping of the classes is a reading of that analysis, not a measurement — the ablation at the end is how to confirm it per module. Do not edit by hand.

**for the check** = the objects the rule is about, the ones a dataset has to carry. **aircraft** = the aircraft and its parts: geometry plus, through the tracker, the stage anchors (the stage detector, PF-Q1-03, is meant to own the second use). **traffic** = other ground equipment, mostly read to answer "is something in the way". **derived** = not detections: `obstacle` / `side_obstacle` are synthesised from the transport and vehicle boxes, `roi` and `safety_zone` are drawn regions. ## Where a small model would be enough

**Nothing from the aircraft or the traffic around it** — a detector of the check's own classes plus the models the module already carries:

- **safety-vests**: detect person, safety_vest; own models: Swin-T pose classifier pose_classifier.pt, Swin-T vest classifier vest_classifier.pt, HSV colour segmentation rules vests_utils.py; tracked: person. Real time: yes, verdict at session end.

**Four classes or fewer, including the aircraft parts it measures against**:

- **steering**: detect chock + airplane_nose; own models: mmpose HRNet-w48 td-hm, tsai time-series classifier model_newaug.pkl, joblib scaler.gz; tracked: airplane, person; it also derives the stage itself from the tracker's optical-flow fields.
- **3-stop**: detect cone + airplane; own models: —; tracked: airplane, beltloader; it also derives the stage itself from the tracker's optical-flow fields.
- **huddle**: detect cone + airplane; own models: —; tracked: airplane, person; it also derives the stage itself from the tracker's optical-flow fields.
- **seat-belts (out of scope)**: detect beltloader, fuel_truck + airplane_engine; own models: mmpose, own norfair person tracker; tracked: airplane, gse; it also derives the stage itself from the tracker's optical-flow fields.
- **crew-present**: detect cone, person + airplane; own models: —; tracked: airplane; it also derives the stage itself from the tracker's optical-flow fields.
- **pin-verification**: detect person, pushback + airplane, front_wheel; own models: mmpose simcc_res50; tracked: airplane, person; it also derives the stage itself from the tracker's optical-flow fields.
- **safety-zone**: detect cone, person + airplane, front_wheel; own models: mobile_sam.pt; tracked: airplane; it also derives the stage itself from the tracker's optical-flow fields.
- **chocks-and-cones-staged**: detect chock, cone, person + airplane; own models: —; tracked: airplane; it also derives the stage itself from the tracker's optical-flow fields.

**What a small model does not solve.** A short class list is not the same as independence: 24 of 27 modules also work out the stage themselves from the aircraft track (T_arr, T_dep, pushback attached, belt loader at the door), and most of them read the synthesised `obstacle` / `side_obstacle` rows to decide "the view was blocked, not observed". Taking a check off the General Model therefore needs three things, not one: its own detector, the stage anchors from the stage detector (PF-Q1-03), and a decision about what plays the part of the obstruction rows.

## How to confirm a class list before collecting for it

The branch can already hand a module only the rows of the classes it declares (`scripts/run_module.py --subscription`, `pf/rt/component.py`), and the whole test set has been run that way: with the declared classes the verdicts are identical to the full inputs on 740 of 740 task verdicts (`docs/analysis/rt_module_cost.md`, section 6). The same machinery narrows the list further: give a module only the classes of the column *for the check* (plus the aircraft if it measures against it) and compare the verdicts with the full run. What survives that is the class list a dedicated model has to cover; what breaks shows which of the other classes the rule really uses.

```
python scripts/run_module.py --module <module> --video <video> --inferences-dir out/testset/v2_inf/<video> \
    --subscription --subscription-parts gm --subscription-extra-gm <class,class>   # rows of these classes only
```
