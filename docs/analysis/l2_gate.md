# L2 gate — module verdicts on GM v2 inputs vs production inputs

Status: first run 2026-09-14 (PF-Q1-15 / PF-Q1-16). Tool: `scripts/run_module.py` (production module code as is, pixel-free
modules with `--no-video`). Raw results: `docs/analysis/l2/l2_DjwtQRdZyt0sSk_prod_vs_v2gm.json`.

## Setup

- Video `DjwtQRdZyt0sSk` (ATL-C5, 37 530 frames).
- **Production inputs**: the production GM second-run file and the production tracker file from ATL-C5.
- **GM v2 inputs**: the v1-compat second-run file regenerated by GM v2 (`scripts/gm_v2_run.py --parallel-heads`, fixed ORT
  options) with the **production tracker file** — this run isolates the GM; the Tracker v2 run on GM v2 rows is next.
- The 12 modules that never read pixels (`docs/analysis/module_consumption.json`, `reads_frames: false`), same code, config
  and `cone_camera=true` on both sides.
- Pins: `beltloader-chocks` runs its own `cv_common` pin (ac5098d2). The other 11 modules pin `cv_common` commits that are not
  in the local archive (86731e4c, dd5b5547, 33c188d0), so they run with ac5098d2 — the same code on both sides of the
  comparison, which is what the A/B needs; absolute verdicts may differ from production's own run of those modules.

## Runner lessons (fixed in `scripts/run_module.py`)

- Modules write logs into `output/` in their folder — the runner creates it.
- Several modules read `dataset.nframes` (default stop frame) even without pixels — the no-video worker returns a stub dataset.
- `detect()` returns 2 to 5 values depending on the module — the runner records the first three and keeps the rest.
- Import errors are recorded in the result JSON, so a missing result can never be reported as "equal".
- YOLOv5-style `select_device` needs `--device 0`, not `cuda`.
