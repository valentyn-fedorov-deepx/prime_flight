## 0. How data reaches a module (db_worker)

- GM ndjson: `{'<frame_ii>': [[x1,y1,x2,y2,conf,cls_id], …]}`; the key is db_worker's own 1-based counter `frame_ii`, not the `frame_id` from `model_pub()` (`ML_worker.py:223,:286,:309,:321`).
- Tracker ndjson: `{'<frame_ii>': [{cls_str, tr_id, xyxy, state_dict{…}, data{bl_type}|null}, …]}` — the shape is derived from `Track().from_json()` in all modules, from the raw access in `hand-signals/main.py:772-774` and from `gat-streaming/streaming/simulate.py:90-103`.
- The frame join is positional: `zip(metadatas['general_model'], metadatas['trackers'])` and `list(j.values())[0]` — the keys are discarded (`ML_worker.py:244-248`). Modules number frames with `enumerate(metadata, 1)` → numbering = position (X2).
- GM producer (`general_model/main.py`): record `[*xyxy, float(conf), int(cls_id)]` (:551,:774); `chock` from a separate model (:586), `vehicle` from another separate one (:592); synthesized `side_obstacle`/`obstacle` (:823,:829, with a stale `conf`); the airplane record `[*bbox, int(mode_plane_height), str2id['airplane']]` (:854) — the conf slot holds the height mode computed over the ENTIRE first run (:701-702). GM itself is two-pass (:517-710 → :745-871).
- `state_dict['_status']` is compared with `Status.STOPPED.value` (`hand-signals:463`) → serialized as the enum value; 5 members are used: MOVING, STOPPED, STOPPING, PROCEEDING, UNOBSERVED.

## 3. GM v2 / Tracker v2 compatibility checklist

**Must stay byte-for-byte (otherwise modules break silently):**
1. A GM record = exactly 6 elements `[x1,y1,x2,y2,conf,cls_id]`: all modules unpack `*xyxy, conf, cls` (an extra column would end up in xyxy), `hand-signals` reads `det[5]`/`det[:4]` positionally (:785-786). bbox in 1920×1080 pixels, clamped (`general_model/main.py:202-217`), modules cast `map(int, xyxy)`; `config['width']/['height']` = 1920/1080 is baked into the ROI logic.
2. `cls_id` is an int, value = `cv_common/global_config.yaml: str2id` on the module's pin; no id outside `str2id` (7 modules with reverse lookup, §2.1). Class set ≥ §2.1 (26 decision + 3 cosmetic: `airplane`, `roi`, `safety_zone`); `air_conditioning` is in the GM `str2id` (`general_model/main.py:480-483`), but no module reads it.
3. Synthesized `obstacle`/`side_obstacle` records (GM second run) — keep them or move their logic into the modules; the airplane record in `general_model` must NOT be removed without checking: `cones-are-removed:145`, `fod-walk:348` access `str2id['airplane']` (colour/drawing only).
4. Track JSON: keys `tr_id`, `xyxy`, `cls_str`, `conf`, `state_dict`, `data.bl_type`; `state_dict` must pass `from_state_dict` of the cv_common class on the module's pin (**unknown keys = ValueError**, proven by the `_bl_type_*` incident, `gat-streaming/docs/contract.md`) — i.e. the key set is fixed in both directions: nothing can be added or removed. Keys the modules read directly: `_class_name`, `_obj_id`, `_xyxy`, `_status`, `arrival_frame`, `departure_frame`, `_p0`, `_st` (a mask of length `len(prev _p0)`, numpy after restore), `_of_dots_lifetime`, `_init_dots_lifetime`, `_static_frames`, `_moving_frames`, `_stopping_time_thres`, `_display_proceeding_time_thres`, `_is_stopped`; the full observed list (39 airplane / 34 vehicle) — §0.1 and the JSON.
5. The semantics of `arrival_frame`/`departure_frame` as absolute ids equal to the position in the stream (4 modules compare with `==`); `Status.value` — the strings `stopped|stopping|moving|proceeding|unobserved` (4 of 5 observed).
6. One GM line and one tracker line for EVERY frame (the join is positional, `ML_worker.py:244`); an empty frame = `[]`, but 15 modules will then not update the track (§2.5) — a gap-fill placeholder must contain at least the airplane track, or this degradation has to be accepted.
7. `bl_type` ∈ {front, back, undefined} and the properties `Vehicle.is_stopped`, `stops_count`, `init_xyxy`, `Airplane.arrived/departured/have_pre_arrival_stage` — the semantics are invisible (cv_common), change only together with the cv_common pin (PF-Q3-05).

**Can be versioned (via `schema_version`):**
- new `state_dict` keys — only if `from_state_dict` on all 10 pins accepts them (today it does not); the safe path: new fields in `data{}` (it is read only via `.data['bl_type']`) or in a separate frame field (`stage`, `events`, `anchors`) — no module reads those;
- `conf` in the airplane record (breaks nothing), `conf` of other classes — only `aircraft-chocks` and `seat-belts` are sensitive;
- the order of records within a frame: `reversed(det)` in 9 modules picks the first match — all else being equal, the result depends on the order (`all-cargo:156`, `chocks-and-cones:96`, `huddle:359`, `safety-vests:332`, `seat-belts:501`, `steering:735`, `conditioned-air` — no).
