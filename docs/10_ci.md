# What is tested, where, and what cannot be

Three rings, by what each one needs. A gate lives in the innermost ring that can actually run it.

| ring | where | needs | what it proves | how long |
|---|---|---|---|---|
| **fast gates** | GitHub Actions, every push and pull request (`.github/workflows/ci.yml`) | python + ffmpeg, no GPU, no weights, no videos | the contract, the receiver, GM and tracker mechanics, the real-time runtime, the component layer | ~1 min |
| **gpu gates** | the machine with the RTX card, on demand (`.github/workflows/gpu-gates.yml`, dispatch-only) | weights (DVC), `external/` module checkouts, real videos | a real module in the branch on a real event: verdicts, cost per frame, latency | 10–40 min per run |
| **the monthly set** | the same machine, orchestrated (`scripts/testset/orchestrate.py`) | all of the above plus ~350 GB of video | accuracy of every module on 69 events, v2 against production | days |

## Fast gates (what runs on every push)

1. `ruff check --select E9,F63,F7,F82,F811` — the defect classes that break at runtime (syntax, undefined names,
   redefinitions). Style is reported separately and does not block: ~450 findings are a known backlog.
2. `pytest -q` — 186 tests, ~10 s. Contract and session, GM v2 (rows, context, camera, second pass, buffered decisions),
   Tracker v2 (stream, events, parity, fast paths), the real-time runtime, the module shell, the component layer, the
   live page.
3. `python scripts/ci_rt_smoke.py` — the branch end to end on a clip ffmpeg generates on the spot: chunker → receiver →
   decoder → adapter → outputs, then the same with 30 % chunk loss and again with per-frame ingest. It asserts the
   invariants, not a model:
   - every frame arrives exactly once and in order (X2);
   - a lost chunk becomes placeholder frames without shifting a single frame id (X2);
   - the decoded frame count matches the manifest (X4);
   - per-frame ingest removes the chunk wait.
   The run leaves `out/ci/rt_smoke.json` as an artifact of the build.

The environment is pinned in `requirements-ci.txt`: pytest, numpy, opencv-python-headless, psutil, filterpy,
scikit-image, PyWavelets, PyYAML, ruff. Deliberately absent: torch, onnxruntime, ultralytics. One test skips without
torch (`test_gm_camera`); everything else runs.

## GPU gates (what cannot run on a hosted runner)

A hosted runner has no GPU, no weights and no access to the private module repositories, so nothing that runs a real
module can live there. `gpu-gates.yml` is written for a self-hosted runner labelled `gpu` and is **dispatch-only**: it
never queues by itself, and until such a runner is registered (PF-Q1-07, blocked on Ihor) it simply does nothing. The
same runs are available locally today:

```bash
python scripts/rt_watch.py --video zHxIAF2vUGxJ_6961_12007.mp4 --module 3-stop-brake-check \
    --extra-modules pushback-pathway-confirmed-clear-of-obstacles --pause-testset
python scripts/rt_slices.py --video <event>.mp4 --cut --run      # rehearse on the minutes that decide
python scripts/rt_components.py --measure <event>.mp4            # the component table
```

## There is no deployment step, on purpose

Nothing in this repository is deployed. The production pipeline runs in DeepX's GCP/GKE from the `dxgat/*` repositories;
this workspace holds the new branch (`pf/`), its measurements and the decisions behind them. So "CD" here means: the
artifacts of a run (reports, component outputs) are attached to the build, and the GPU gates publish theirs the same way.
When the real-time branch needs a home outside this machine, the step to add is a container image for the GPU box —
CUDA, the weights from DVC, the module checkouts — not a hosted deployment.

## Secrets

None are needed and none are stored. GCP, MongoDB and GitLab credentials stay on the machines that already have them;
the fast gates need no access to anything. Weights and videos are never in git (`docs/08_repos.md`).
