## Goal

Every module that feeds a real-time alert fits the frame budget with its verdicts unchanged, or with a measured and approved
minimal loss. Lightening comes in three risk classes, and each class has its own gate (below), so that "lighter" never
silently means "worse".

## Quality gates

| class | what changes | gate |
|---|---|---|
| **EXACT** | nothing observable: batching at the same precision with deterministic kernels, caching a computation whose inputs do not change, removing dead model loads, debug drawing and per-frame logging, sharing an identical model with identical preprocessing, crops instead of full frames, shared decoding | verdict, report and smart timeline byte-identical to the batch control on the module sample (10 events, `out/testset/modules/ctl`), plus model outputs bit-identical on a slice |
| **NEAR** | small numeric change: ONNX Runtime / TensorRT export, fp16 | verdict parity with the control on all 69 events of the monthly report (production GM / tracker rows are local for all 90 videos; videos re-fetched for pixel modules); every flip explained; accuracy against the validated truth not lower |
| **SEMANTIC** | can change verdicts: temporal subsampling, a smaller or shared model with different preprocessing, own tracking replaced by the shared tracker, a removed pass, a changed trigger | accuracy against the validated truth on the 69 events, per task, approved by Oksana / Ihor; tag `trigger-change` when the trigger changes (as PF-Q3-06) |

## Steps

1. **Cost profile per active frame** in the RT harness: per module and stage window — decode and crops, each model, logic,
   state restore; peak RAM / VRAM → `docs/analysis/rt_module_budget.md`; on a free machine.
2. **Variant gate harness**: run a module variant (branch or overlay) against the control and report its gate class.
3. **EXACT fixes** from the compute inventory (`docs/analysis/module_compute.md`), module by module, through the gate.
4. **Shared frames and crops** in the RT branch (with PF-Q2-01): decode once per camera, a frame ring buffer sized by the
   longest look-back, a crop cache; no decoding and no full-frame buffers inside modules.
5. **Shared model runtime** (with PF-Q2-02): one process per GPU, each unique weights file loaded once, crops batched across
   modules and cameras.
6. **NEAR and SEMANTIC** changes per module, only through their gates.
