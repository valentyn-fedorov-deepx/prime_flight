## Key points (for whoever will not read the 375 lines)
1. GM job = one full-turn video of one camera; `model_starter.py` from db_worker: `dvc pull` → `detect()` → gzip-ndjson to
   `gs://cv-modules-topics/<video>.mp4/general_model<commit>.ndjson` + a Kafka report. GM does not touch MongoDB.
2. `detect()` makes **three full passes** over the video (3 readers opened up front + a fourth in `get_video_info`):
   1) 3 ONNX YOLOv8 (GM@1088, chocks@1280, vehicle@1088) + Norfair/SAM aircraft tracking; 2) repeated decode + enrichment;
   3) `select_video` frame-diff, whose result nobody reads.
3. The modules and the tracker read **the second-pass file**: raw `airplane` rows dropped, one main aircraft per frame with
   **the height mode (e.g. 680) in the conf slot**, `obstacle`/`side_obstacle` rows = copies of boxes with a constant `conf`
   (`main.py:823, 829`). Row format `[x1,y1,x2,y2,conf,cls]`, 1-based keys = the writer's counter, no `schema_version`.
4. Per-video decisions: main aircraft, height mode, parts layout, stages — **need the whole video** (argmax after EOF);
   camera type — incremental majority, but finalized after EOF (there is an unused 20-min window `main.py:734`);
   entity (40 hits) and aircraft type (500 votes) — decided early.
5. Dead/broken: BL stages always False (`front_door`/`back_door` are never populated), `stages=None` in the report,
   noise/`is_broken` are lost at the job boundary, CPU mode is non-functional (`.cuda()` without a condition), `timm(pretrained=True)` pulls weights from the network.
6. Perf: batch=1 everywhere, ≈41 % of compute on the padding of square inputs, per-row GPU→CPU synchronizations, SAM on every frame,
   `write_video` default True in prod.

## Recommended GM v2 plan (from §10 of the report)
- `gm_core`: a pure `frame → rows` with the same thresholds/letterbox/fp16/NMS → bit-for-bit parity of the raw rows.
- `gm_context`: incremental decisions with `decided_at` events (entity, aircraft type, camera, layout, main aircraft).
- Two sinks: the v2 bus (`schema_version`, `frame_id`, raw rows) + a **v1-compat writer** that at the end of the event reproduces
  the legacy second-pass file → the 27 modules and the tracker do not change; parity is checked bit-for-bit.
