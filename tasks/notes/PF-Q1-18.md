# PF-Q1-18 — Monthly test set on GM v2 + Tracker v2

**Owner:** Valentyn (+Yurii) · **Agents:** gm-tracker-engineer, qa-parity · **Status:** in progress (started 2026-09-14)

## Goal

Run the monthly CI test set (report of CI job 16263924101: 69 events, 90 videos, 31 tasks) through all modules on the
GM v2 + Tracker v2 inferences. The verdicts must stay the same as production while GM + Tracker cost less.

## Method

- **Reference 1 — the report's "New output"** (the CI). It cannot be reproduced exactly offline: the CI image
  (`ci-cv-module-image`, `ci.py`) is not accessible, modules are built with `cv_common_branh: master`, and the camera type
  comes from the database (`videos_by_module[...]['cameraType']` in each module's `run_module.py`).
- **Reference 2 — the control**: the same module code, flags and machine on the production inferences (GM 8576299 +
  tracker bd43c3c, the latest files in `gs://cv-modules-topics`). The paired comparison v2 vs control isolates the effect of
  GM v2 + Tracker v2 from everything else that differs from the CI.
- Per video, `scripts/testset/orchestrate.py`: fetch → GM v2 (`--variant entity_clip --parallel-heads`, tolerant L1 vs the
  production GM file) → Tracker v2 (`--exact-fast --seed 0`, L1 vs the production tracker file) → every module on the
  production inferences (`out/testset/modules/ctl`) and on the v2 inferences (`out/testset/modules/v2`).
- Task verdicts per event as the report builds them (two-camera merge Fail > Pass > Not observed; the stop-brake +
  hand-signals task derived): `scripts/testset/compare.py --runs-root .../v2 --baseline-root .../ctl`.
- Flags: camera from the report routing (`scripts/testset/plan.py`), aircraft type per event where the report implies it;
  both labels get the same flags.

## Environment deviations (identical for control and v2)

| module(s) | deviation | why the paired result is not affected |
|---|---|---|
| lead-marshaller, pushback-does-not-start, wing-walkers | `--numpy1-scalars` | NumPy 2 rejects `float()` of one-element arrays; the shim restores exactly the NumPy 1.x conversion |
| modules whose cv_common pin is not in the local archive | cv_common ac5098d2 (master) substituted, recorded in `cv_common/SUBSTITUTED_PIN.txt` | the CI builds modules with cv_common master as well |
| pre-departure walk-around | norfair 0.3.1 overlay `out/envs/norfair031` | the version pinned in the module requirements |
| post-arrival and pre-departure walk-arounds | `--drop-state-keys` for the six `transport.Airplane` stage keys | the modules' own `Airplane(TrackedObject)` never reads them; that cv_common copy already drops `arrival_frame` the same way |
| hand-signals, steering, pin-verification | mmpose 1.x overlay (in progress) | — |
| hair-policy | Pyarmor build for Linux Python 3.10 → WSL runtime (in progress) | — |

## Findings so far

- **Control reproduces the CI**: on event 641a25728471f56e528714e9 (zHxIAF2vUGxJ) the modules on GM 8576299 + tracker
  bd43c3c match the report's New output on 11 of 12 pixel-free tasks (exception: cones_in_position fail vs Not observed,
  validated Not observed). Rejected on this event: a wing camera flag (7 of 11) and the pre-August files GM d5ef0b0 +
  tracker b5d350c (9 of 12). An earlier 9-of-12 figure for the production files came from a NumPy shim that broke
  `np.dtype(float)`; fixed before these runs.
- **GM v2 entity_clip** on zHxIAF2vUGxJ vs the production GM file: pair recall 99.93 %, frames within tolerance 92.1 %
  (the ATL-C5 runs of the prod variant, without the heavy-frame stabilizer: 55–88 %).
- **Tracker v2** on the production GM rows vs the production tracker file: 48 999 / 48 999 objects matched, 26 / 26
  identities; events equal except BL_AT_DOOR +4, BL_LEAVE +24, T_ARR +1 and T_DEP +52 frames — the tracker's own
  run-to-run randomness (production runs are not seeded; Tracker v2 is byte-identical to the pin under a shared seed).

## Cost

Timings logged during the run are under contention (8 CPU threads; one GPU shared by GM, two trackers and modules) and are
not cost figures. Clean references so far: GM heads v1 op sequence 22.4 → parallel 16.75 ms/frame, byte-identical
(TensorRT 8.0, tolerant only, ADR-003 proposed); GM v2 full turnaround 28.3 ms/frame; Tracker v1 50.6 → v2 exact-fast
39.2 ms/frame, byte-identical under a shared seed. A clean paired run on test-set videos closes this section.
