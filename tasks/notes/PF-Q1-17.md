# PF-Q1-17 · Tracker v2 in `pf/tracker` (per ADR-001)

- **Owner:** Yurii + Valentyn · **Agent:** gm-tracker-engineer · **Status:** in-progress (port and exact fast paths proven byte-identical) · **Quarter:** Q1
- **Deps:** PF-Q1-13 (tracker as-is, review), PF-Q1-14 (contract), PF-Q1-16 (GM v2) · **Tags:** speed, parity
- **Repo / branch:** this repo, `pf/tracker` (contract + interface so far), `scripts/tracker_v1_profile.py`, `scripts/win_shims/`

## Goal (lead's mandate, 14.09)
The tracker must become **lighter and much faster** while the modules' accuracy does not degrade: same `state_dict` on the
consumed fields (`pf/tracker/contract.py`, `module_consumption.json`), same identities (X1), same arrival/departure
frames within ±1–2 frames, 0 verdict changes on the L2 gate. Private fields (`_p0`, `_st`) leave the bus (ADR-001 §3).

## Baseline measured 2026-09-14 (RTX 5070 Ti, 1080p, `DjwtQRdZyt0sSk`, two 1 200-frame slices)

The v1 tracker was never measured before (the stand hard-codes `tracker = 0.11 ms`). `scripts/tracker_v1_profile.py`
runs the unmodified `tracker.detect()` of a pin on a slice (GM ndjson truncated and renumbered, video seeked) with timing
wrappers; raw reports in `docs/analysis/speed/tracker_v1_profile_*.json`. Slice "arrival" = frames 3 400–4 600 (aircraft
arrives at 3 465, first GSE), slice "busy" = 9 000–10 200 (beltloader at the door, GSE, up to 8 tracks/frame).

| pin | slice | **total ms/frame** | `update_params` (state machine) | optical flow PyrLK | DeepSORT ×3 | `estimate_sigma` | masks | `model_pub` | rest (decode + loop) |
|---|---|---|---|---|---|---|---|---|---|
| master b5d350c + cv_common ac5098d (MobileSAM) | arrival | **137.4** | 14.4 | 5.7 | 5.9 | **100.1** (every frame) | SAM 4.4 (13 % of frames) | 0.5 | ≈ 17 |
| master | busy | **148.7** | 25.4 | 9.7 | 9.1 | **102.5** | SAM 8.0 (26 %) | 0.8 | ≈ 11 |
| **production** bd43c3c + cv_common 2759daf (YOLO-seg) | arrival | **35.8** | 12.1 | 6.9 | 6.0 | 6.7 (every 16th frame) | YOLO-seg 2.2 (13 %) | 0.5 | ≈ 10 |
| production | busy | **48.7** | 20.2 | 10.9 | 9.6 | 7.0 | YOLO-seg 3.8 (26 %) | 0.8 | ≈ 11 |

(`update_params` includes optical flow and masks; the "rest" is OpenCV decode ≈ 3 ms + the per-frame Python loop: two
`cvtColor` per object, three full-frame copies, GM row parsing, DeepSORT input packing.)

Facts that decide the design:
1. **The master pin is slower than real time** (7.3 fps at 8 fps input) because of `skimage.estimate_sigma` on the full
   1080p frame on every frame with any tracked object (161 ms per call on this CPU; the TV denoiser it gates never fired on
   ATL-C5 daylight). Production throttled it to every 16 frames (`estimate_sigma_interval: 2` s) but still on the full
   frame (the crop code is commented out) → 107 ms per call, 7 ms/frame amortised.
2. After that, production's cost is the per-object state machine: PyrLK optical flow on ≤ 250 points per object per frame
   (7–11 ms/frame), DeepSORT ×3 with a ResNet34 ImageNet ReID for BL/GSE (auto-downloaded torchvision weights, 83 MB —
   not the DVC checkpoint; the `.t7` re-id is only for persons) 6–10 ms/frame, YOLO-seg 2–4 ms/frame amortised.
3. The production backend already differs from master in the consumed fields: on the busy slice (same 4 identities, all
   3 186 object-frames matched) `_status` differs on 88 object-frames (2.8 %), `_is_stopped` 106, `_stops_count` 20,
   `_static_frames` 112 (`pf.eval.compare_tracker_ndjson`). Different masks → different keypoints → different stop timing;
   plus unseeded `np.random.choice` of keypoints. **Tracker v2 is compared with the production pin.** Its run-to-run
   noise floor (same code, same slice, two runs): identities and `_status`/`_stops_count` identical on all 3 186
   object-frames, only `_moving_frames` 5 and `_is_stopped` 1 object-frames differ (0.2 %), `_p0` differs on 7 % — so the
   2.8 % status gap master↔production is behavioural, and the v2 criterion can be strict (below).
4. YOLO-seg cache-key collision in cv_common 2759daf (BL and GSE share the `'Vehicle'` key with different `classes=`,
   `tracker_current.md` §12) — a correctness bug to report, and the reason mask sharing per class must be explicit in v2.

## Tracker stream port and exact fast paths — proven 2026-09-14

- `pf/tracker/stream.py` (`TrackerStream`): the production loop of `cv_trackers/tracker.py` @bd43c3c as a causal
  per-frame class (`update(frame_number, frame, gm_rows)` returns the records that became final, `finish()` flushes the
  publish buffers), on the production classes vendored verbatim into `pf/tracker/_v1` by `scripts/vendor_tracker_v1.py`
  (cv_common @2759daf; `deep_sort_pytorch` and configs @bd43c3c; helper functions AST-extracted with their dependency
  closure). Outputs: the v1-compat file in the byte format of `VideoWorker.model_pub` (keys = write counter) and the v2 bus
  (absolute `frame_id`, no `_p0`/`_st`): **2.7 MB instead of 29.7 MB** for the 1 200 busy frames, 10.8× lighter.
- **Proof method.** v1 subsamples keypoints with unseeded `np.random.choice`, so `scripts/tracker_v1_profile.py --seed`
  seeds NumPy when the production pin pulls its first frame, and `scripts/tracker_v2_run.py --seed` seeds right before the
  first update. On the busy slice (frames 9 000–10 200 of `DjwtQRdZyt0sSk`) **the v2 port is byte-identical to the
  production pin: 1 200 of 1 200 lines, including the private optical-flow fields.** Against an unseeded production run
  only 17 lines match, so the seed alignment is what makes a byte-level comparison possible.
- The proof caught one porting bug on its first run: the vendoring copied helper bodies without their imports
  (`get_distance` lost `from math import sqrt`) and the run crashed at the first airplane stop point, after 668 lines that
  were already byte-identical. The generator now resolves every free name or aborts, and builds atomically.
- **Exact fast paths** (`TrackerOptions.exact_fast`, `--exact-fast`): grey frames once per frame with masked copies per
  distinct box list, a vectorised in-box test of the tracked points and no per-frame airplane `print`
  (`pf/tracker/fast_paths.py`, methods rebuilt from the pinned source with guarded one-line substitutions); no full-frame
  copies; the bit-identical threaded noise estimate (`pf/tracker/fast_sigma.py`, 49 ms instead of 108 ms per call); the
  three DeepSORT updates in parallel threads. **Also byte-identical: 1 200 of 1 200 lines.**
- **Grouped optical flow** (`pf/tracker/fast_grouped_lk.py`, part of `exact_fast`): OpenCV tracks every point independently,
  so beltloaders or GSE sharing one masked grey pair and direction can go through one `calcOpticalFlowPyrLK` call
  (bit-identical per object; 15.2 → 5.7 ms for three objects). The object update is split exactly at that call, the class
  loops keep the order of every effect, and the replicated vendored lines and their statement counts are checked at start.
  **Byte-identical on both slices** (busy and arrival, 1 200 of 1 200 lines each, against seeded production-pin references).
  On this video it rarely merges calls, because one beltloader and one GSE are tracked at a time (557 calls for 559 objects
  on the arrival slice), so its gain shows only on turnarounds with several loaders.
- **Whole video (2026-09-15, test set):** zHxIAF2vUGxJ.mp4 and MwCSLbQ7QvXQ.mp4, 17 280 / 17 280 and 18 450 / 18 450 lines identical between Tracker v2
  (`--seed 0 --exact-fast`) and the production pin with seed 0 on the same GM v2 rows (only the line terminator differs:
  CRLF vs LF); `scripts/testset/tracker_exact_check.py`, `tasks/notes/PF-Q1-18.md`.
- The noise estimate now transforms axis 0 on a transposed contiguous copy and drops zeros with a boolean mask: still
  bit-identical, 41.6 ms per call instead of 57.3 ms (145.6 ms for scikit-image), measured under contention.
- Speed under the same contention on the arrival slice: pure port 36.7 ms/frame, exact fast paths 28.3 ms/frame (−23 %).
- DeepSORT's cost is the ReID network, not the matching: 15.3 ms/frame of thread time in the ResNet34 extractor (1.8 of it
  CPU preprocessing), 1.5 ms in the person network, 0.6 ms matching, 0.1 ms Kalman prediction (600 busy frames). YOLO-seg
  costs about 27 ms per call at 0.2 calls per frame: 2.5 ms preprocessing, 15 ms inference, the rest mask postprocessing.
- **Production quirk in the DeepSORT ReID (found 14.09).** The beltloader and GSE trackers build `ResNetExtractor`
  (torchvision ResNet34, ImageNet weights) without `.eval()`, so its 36 BatchNorm layers run in training mode and every crop's
  feature depends on the other crops of its class in the same frame (up to 7.25 absolute difference when beltloader and GSE
  crops share a batch; only the person network is switched to eval). Merging the two ReID batches or changing the batch
  composition is therefore not exact, so the exact fast path keeps separate per-class batches in parallel threads. Eval mode
  would make the features deterministic and batch-independent — a candidate accuracy improvement for a versioned tracker,
  to be judged by the identity and consumed-field comparison and the L2 gate, not assumed.
- **Events for the stage detector (PF-Q1-06).** `pf/tracker/events.py` derives T_ARR, T_DEP, BL_AT_DOOR and BL_LEAVE causally
  from the published records (v1-compat file or v2 bus), without touching the tracker loop: arrival and departure from the
  airplane state, door occupancy per door from `data.bl_type` (a different track id on an occupied door is a re-identification,
  a door is left when its occupant's label returns to 'undefined', which the tracker does only when the loader starts moving).
  On the production tracker file of DjwtQRdZyt0sSk: T_ARR 3 669, front door occupied 9 888–22 776 with one re-identification
  (85 → 88 at 21 945) — exactly the timeline beltloader-chocks reports (9 888–22 775). `scripts/tracker_events.py` compares
  event frames between tracker files (next: production vs the GM v2 + Tracker v2 pipeline).
- **PUSHBACK_ATTACHED (`pf/stage/pushback.py`).** aircraft-chocks computes it itself in two passes. When its first pass finds a
  median pushback box (from a window 120 s to 60 s before departure, i.e. it looks ahead) it counts frames whose pushback
  overlaps that box with IoU > 0.8; otherwise it counts frames where the pushback reaches the nose. The nose rule is causal and
  is ported exactly; the median rule is replicated offline to measure the difference (`scripts/pushback_events.py`,
  `docs/analysis/stage/pushback_attached_atlc5.json`). On the 7 ATL-C5 videos production used the nose rule on 5 and the causal
  frame is identical on all 5; on the 2 videos where production used the median rule the causal rule fires earlier (−183 frames
  = −23 s on AIjEAz70OfWCYG, −18 frames on vwksGNQQwqjT0I). Two production frames look too early to be real attachments
  (iE9pRtOwlwj9XY 98 s after arrival, OKK5AlUiZnACMm 7.6 min after arrival): a pushback parked near the nose satisfies the nose
  rule — to be checked on video with the aircraft-chocks owners.
- **Full video through the new pipeline (GM v2 second-run rows → Tracker v2 exact fast paths, seed 0, cone camera).** The stage
  events equal production's: T_ARR 3 669, front door occupied 9 888–22 776, the occupant re-identified at frame 21 945 — every
  frame identical (`docs/analysis/stage/events_DjwtQRdZyt0sSk_production_vs_gmv2_trackerv2.json`); only DeepSORT's id numbers
  are offset by two (87 → 90 instead of 85 → 88), because GM v2's rows differ in a few detections. Tracker cost over the 37 530
  frames: 35.4 ms/frame while the GM chain shared the GPU; grouped optical flow served 36 221 object updates with 35 286 calls;
  the v2 bus is 57 MB against 597 MB for the v1-compat file. L2 on these inputs is running.
- Speed on the same slice, measured while the GM chain was using the same GPU and CPU (relative only; an idle re-run is
  pending): pure port 50.6 ms/frame, exact fast paths **39.2 ms/frame (−23 %)**. `cvtColor` 3.07 → 0.66 ms, noise
  estimate 7.34 → 3.12 ms, frame copies 1.3 → 0 ms, state machine 23.2 → 19.5 ms. The parallel DeepSORT threads gain
  little, because the three updates are GIL-bound Python around small ReID batches.
- Cost left after the exact paths: optical flow 10.4 ms (OpenCV's Python binding cannot take pre-built pyramids),
  DeepSORT about 11 ms, YOLO-seg 5.5 ms, decode 2.5 ms. The next steps change numerics, so they need the L1-tracker
  tolerance criterion and the L2 gate (see Design).

## Design for v2 (lighter + faster, same semantics)
Keep byte-for-byte: DeepSORT configs and identity rules, the `analyze_movement` state machine and thresholds, the airplane
counters and `arrival_frame` rewrite, `state_dict` key sets/order (contract). Change only cost and plumbing:
- **Noise gate**: `estimate_sigma` on a 4× downscaled frame (or the GPU) every N seconds — < 1 ms/frame; keep the 0.5
  threshold semantics (calibrate on the same frames: the sigma of the downscaled image must map to the same decision).
- **One gray frame per frame** (not two `cvtColor` per object), no full-frame copies without `--save-video`.
- **Masks**: one YOLO-seg inference per frame for all classes (batched, shared), explicit per-class results (fixes the
  cache-key collision); masks only when a track re-initialises its keypoints (as now).
- **ReID batched**: one ResNet34 forward for all BL + GSE crops of the frame (two instances today).
- **Optical flow**: unchanged algorithm and parameters (its output is the state machine's input); shared pyramid per frame
  (`cv2.buildOpticalFlowPyramid` once, PyrLK per object) — identical results, saves the per-object pyramid rebuild.
- **Bus**: v2 records without `_p0`/`_st` (80–90 % of bytes); the v1-compat writer keeps them for the 27 modules.
- **Determinism**: seed the keypoint subsampling per (event, frame) — run-to-run reproducible; documented as a versioned
  behaviour (v1 is unseeded).
- Target: **≤ 15 ms/frame on this GPU (3× vs production)**; identities, `_status` and `_stops_count` identical to the
  production pin on the same slices, other consumed counters within the measured floor (≤ 0.2 % object-frames), event
  frames ±1, 0 L2 verdict changes.

## How it will be verified
- L1 tracker: `pf.eval.compare_tracker_ndjson` (consumed fields, identity by `(cls_str, _obj_id)`), events ±1–2 frames;
  the same slices first, then the 7 full ATL-C5 videos against the production tracker files.
- L2: `scripts/run_module.py` on beltloader-chocks, pushback-pathway, bl_rear_cone (pixel-free), then the pixel modules.
- Speed: `scripts/tracker_v1_profile.py`-style wrappers on the v2 core; full turnaround incl. decode.
