# `pf` — Prime Flight core package

Here we assemble, piece by piece, the streaming version of the DXGAT CV pipeline: contract and receiver, GM v2 and Tracker
v2 (ported from production, proven against it, then made faster), the stage detector, then module adapters.

| Package | State | What it is |
|---|---|---|
| `pf.contract` | **done, tests** | Frame contract schema 1.0: `schema_version`, `frame_id`, `general_model`, `trackers` + optional `stage`/`events`/`anchors`; hygiene of field leakage between tracker classes. Ported from the `gat-streaming` stand (test bench). |
| `pf.receiver` | **done, tests** | `Session`: one event = one continuous stream = one tracker (X1); gap filling with placeholder frames (X2); `stream_from_chunks` for transport tests. |
| `pf.eval` | **done, tests** | Parity: `compare_gm_ndjson` (exact per frame) and `compare_gm_ndjson_tolerant` (same-class IoU pairing, ±px / ±conf, delta percentiles — the cross-hardware criterion), `compare_tracker_ndjson` (consumed `state_dict` fields, identity by `(cls_str, _obj_id)`). Streams a 600 MB production file in ~13 s. |
| `pf.gm` | **GM v2 on real weights, proven** | `onnx_detector` (v1-faithful ORT session options, uint8 upload, TensorRT option that refuses a silent CUDA fallback), `heads` (`MultiHeadRunner`: one letterbox per input size, parallel heads — rows byte-identical), `rows`, `context` (+ `context_prod`, `plane_tracker` on a vendored norfair 0.2.0), `compat_writer` (legacy second-run file), `preprocessor`, `camera` (EfficientNet-B0 cone/wing, exact port), `second_pass` (MobileSAM plane → `frame_stopped`, camera votes; bit-identical to the inline v1 reproduction). Full turnaround 28.3 ms/frame = 4.42× real time; pair recall 99.9 % against production; 11 of 11 comparable modules keep their verdicts (`docs/analysis/gm_speed.md`, `gm_prod_delta.md`, `l2_gate.md`). |
| `pf.pipeline` | **done, tests** | `GmStream` (chunk-wise GM driver, v1-compat writer, report), `causal_rows` (second-run rows from the decisions made so far, for streaming). Runners: `scripts/gm_v2_run.py`, `scripts/gm_v2_replay.py` (`--second-pass`), `scripts/stream_pipeline.py` (GM v2 + Tracker v2 on chunks, events, v2 bus frames). |
| `pf.tracker` | **Tracker v2, proven byte-identical** | `stream` (`TrackerStream`: the production tracker loop per frame on vendored production classes in `_v1`, generated by `scripts/vendor_tracker_v1.py`), exact fast paths (`fast_paths`, `fast_grouped_lk`, `fast_sigma` — byte-identical to the seeded production pin, −23 % under load), `events` (T_ARR, T_DEP, BL_AT_DOOR, BL_LEAVE from published records), `contract` (record / `state_dict` checks). `docs/analysis/tracker_current.md` §8, `tasks/notes/PF-Q1-17.md`. |
| `pf.stage` | **events started** | `STAGES`, `EVENTS` (in `pf.contract.frame`); `pushback` (causal PUSHBACK_ATTACHED = the aircraft-chocks nose rule, plus an offline replication of the production two-pass rule). The state machine is PF-Q1-03. |

## Rules for code in `pf`

- The inference core knows nothing about video files, chunks, MongoDB or buckets — only frame → detections / detections → tracks.
- Everything the modules consume today (detection format, `class_id` map, `state_dict` keys, frame numbering from 1)
  stays compatible, or changes via an ADR + `schema_version` (frame level; the tracker `state_dict` is frozen, ADR-001).
- A performance change to ported v1 code must be output-identical and proven: byte-identical rows for the GM heads, seeded
  byte-level runs against the production pin for the tracker. A change that alters numbers is versioned and passes the
  tolerant L1 metric and the L2 module gate on real videos.
- Never add runtime options v1 does not set (the first GM port added one cuDNN option and ran 2.6× slower).
- Unit tests run in seconds; tests that need OpenCV, scikit-image or filterpy skip themselves when those are missing.
  GPU work lives in scripts that write JSON reports, never in unit tests.

```bash
pip install -e ".[ci]"   # or simply: pip install pytest
pytest
```
